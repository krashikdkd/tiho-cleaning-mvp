# Тихо — шаблон витрины выездной химчистки

Локальный демонстрационный MVP на React + TypeScript + Vite. Все тексты, мебель и композиция созданы для этого шаблона. 3D-предметы процедурно собраны из геометрии Three.js в `src/main.tsx`; внешние модели не используются, поэтому отдельных лицензий на модели нет. Для проекта нужны лицензии зависимостей из npm; проверяйте их условия для выбранного способа передачи и публикации.

## Сценарий и расчёт

Клиент выбирает варианты дивана, кресла, матраса, стула или предмет «Другое», формирует заказ и отправляет контакты. Число предметов умножает цену строки. Сильное загрязнение увеличивает тариф на 35%; вторая сторона матраса — ещё на 30%. Проценты умножаются на базовую цену последовательно, результат округляется до 10 ₽ на штуку, затем умножается на количество. Минимальная стоимость чистки — 2 500 ₽ на заказ; фиксированный выезд за город (700 ₽) добавляется после минимума. «Другое» остаётся оценкой по фото и не считается нулём.

## Запуск

Требуется Node.js 20+.

```sh
npm install
npm run dev
```

Production build: `npm run build`; локальный просмотр: `npm run preview`.

Кабинет доступен по `/admin`, демонстрационный пароль — `demo2026`. Демо-заказы остаются в localStorage этого браузера и видны кабинету в том же браузере. Ссылка `/order/<token>` показывает заказ только в том же экземпляре браузера, где он создан.

## Что именно демонстрируется

- адаптивная витрина с переключением светлой/тёмной темы;
- 3D-геометрия предметов, вращение мышью/касанием и сброс камеры через повторное открытие;
- конфигуратор, несколько позиций, количество, отметки загрязнений, отмена последнего удаления;
- черновик заявки и корзина, локально сохраняемые после перезагрузки;
- клиентский просмотр заказа и демонстрационный интерфейс владельца со статусом, ценой и временем;
- демонстрационные разделы тарифов, компании, бонусной игры, персонажей и доступа;
- заголовки, robots, sitemap, manifest, иконка, offline экран-заготовка.

## Перед публикацией: обязательная серверная работа

Это frontend-прототип, а не production-сервис. `localStorage` не является постоянной базой данных, не синхронизирует устройства и доступен самому пользователю. Клиентский пароль не защищает кабинет. Фото не загружаются в закрытое хранилище. Серверного пересчёта, проверки origin, ограничения запросов, идемпотентного приёма, журналирования изменений и управления сессиями пока нет. Поэтому не публикуйте этот демо-вход и не принимайте реальные персональные данные.

Рекомендуемая адаптация для одной компании: Next.js/TypeScript API + PostgreSQL (например, managed Postgres) и приватный S3-compatible bucket. Сервер хранит версионированные тарифы и снимок условий каждой заявки; считает и округляет цену сам; валидирует изображение по декодируемому формату, размеру, количеству и повторно кодирует его; отдаёт фото после авторизации или короткоживущей подписанной ссылки. Случайный idempotency key с уникальным ограничением в БД предотвращает дубли. Кабинет защищается серверной сессией и хешированным паролем, все API проверяют origin, входные схемы, частоту запросов и права. Публичный токен заказа генерируется криптографически случайным, хранится в виде хеша и даёт только просмотр клиентских данных; заметки владельца и фото не включаются в публичный ответ.

Для передачи покупателю надо подключить его домен, серверный хостинг, базу и хранилище, задать секреты, рабочий контакт, территорию, тарифы и юридически проверенные условия обработки данных. Оплата здесь не предусмотрена. Расходы на домен, приложение, БД, хранилище фото, резервные копии и почту/SMS зависят от выбранных поставщиков и нагрузки. Figma/Blender-интеграции в этой среде не обнаружены; дизайн реализован прямо в исходниках, `.blend` не создавался. Новые услуги, платежи, расписание специалистов, CRM, роли и уведомления требуют отдельной оценки.


## Публикация на GitHub Pages

Исходники: https://github.com/krashikdkd/tiho-cleaning-mvp

Опубликованный демо-сайт: https://krashikdkd.github.io/tiho-cleaning-mvp/

Репозиторий собирается GitHub Actions workflow из `.github/workflows/pages.yml`. В текущем репозитории Pages уже включён с источником **GitHub Actions**. Для GitHub Free репозиторий должен быть публичным; опубликованный сайт будет доступен всем, даже если тариф допускает Pages для приватного репозитория. Это статический демо-сайт: общих заказов и закрытого кабинета на GitHub Pages не будет.

Workflow настраивает Vite base path по имени репозитория, а `404.html` сохраняет прямые ссылки `/admin` и `/order/<token>` внутри Pages. После публикации проверьте ссылку из GitHub Actions → Deploy.
